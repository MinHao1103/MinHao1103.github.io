( 十一 ) 延遲載入
===

# ( 1 ) ORM 框架中的延遲載入
:::warning
* Lazy loading，又稱 延遲初始化 ( Lazy Initialization )
    * 惰性載入、懶載入、瀑布流
    * 一種設計模式，指查詢資料時，先儲存識別值，當需要用到資料時，才會進行載入，例如：
        * 當使用者快捲動到該頁底部，才會去載入後續內容，Ex：Facebook
* ORM 框架 映射 "程式端" 與 "資料庫端"
    * 程式端可能只在某時刻關心其中某筆資料
    * 資料庫端可能是大量的資料
    * 若一開始就載入全部資料，會導致效能下降
    * 為了解決此問題，ORM 框架中幾乎都會導入延遲載入 
:::

## ( 1-1 ) Hibernate 中的延遲載入
:::warning
* Hibernate 中的 load()，就有使用延遲載入的機制
    * session.load() 會先取得 代理物件 ( Proxy )，其中含有識別值 ( id ) 
    * 當實體物件透過 Getter 取得任何一個非 OID 屬性之值時
    * 底層才會真正去 SELECT 出所有屬性值
    * 上述呼叫 Getter 取值，應在 Session 未關閉的情況下執行
:::

### ( 1-1-1 ) 延伸問題
:::warning
* Hibernate 為了提高效能，而導入延遲載入機制
* 但實際運用上，常會需要在無連線 ( Session 關閉 ) 的狀態下取得屬性值，例如：
    * 在 JSP 網頁 ( View )，顯示資料，此時 Session 早已關閉
    * 上述情況不僅取不到值，還會拋出 LazyInitializationException
:::

## ( 1-2 ) 配合延遲載入的相關程式
:::warning
* 延遲載入須配合 Session 物件，所以程式須做相關處理
* ( 一 ) 停用延遲載入
    * 將 session.load() 改成 session.get()
    * 透過映射設定停用
    * 透過 Association 設定停用
* ( 二 ) 使用延遲載入，但在 DAO 層強制載入屬性值
* ( 三 ) 控制 Session 物件 開啟/關閉
    * 自訂 Filter，在 Filter 中做交易控制
        * 若使用此方法，須將 Service 層中的交易控制註解
    * Spring：使用 OpenSessionInViewFilter
    * Spring MVC：OpenSessionInViewInterceptor
:::

:::warning

* 方法一：
    * 在 \<hibernate-mapping\> 加上 default-azy="false"
* 方法二：

#### ( 1-2-4-1 ) 使用步驟
:::warning
* 自定義 Filter 類別
    * 新建 Filter 類別，繼承 HttpFilter 類別
    * 覆寫 doFilter()
        * 前置處理：取得當前 Session 物件、開始交易
        * 後置處理：commit / rollback
:::
```java=
@WebFilter("/*")
public class HibernateFilter extends HttpFilter {
    public void doFilter(ServletRequest request, ServletResponse response, FilterChain chain) {
        Session session = HibernateUtil.getSessionFactory().getCurrentSession();
        try {
            Transaction transaction = session.beginTransaction();
            chain.doFilter(request, response);
            transaction.commit();
        } catch (Exception e) {
            session.getTransaction().rollback();
            e.printStackTrace();
        }
    }
}
```
