( 七 ) 實體 類別/物件
===
# ( 1 ) 實體物件(類別) vs. 永續物件(類別)
* Hibernate 映射機制
    * 類別 / 物件 經過映射設定後
    * 即為 "實體" 類別 / 物件 ( Entity Class / Object )
* Hibernate 基本功能
    * 將物件的屬性值，儲存至資料庫端對應的資料表中
* 說明
    * 上述動作稱為 永續儲存
    * 被儲存的實體物件為 永續狀態，稱為永續物件 ( Persistent Object )
    * 因此 Hibernate 也稱為永續層框架 ( Persistent Layer Framework )
    * 在 Hibernate 官方文件中，有時稱此種物件為 Domain Model
        * 可參考 Guide-2. Domain Model
    * 一般會將該類別,定義成 POJO 類別

## ( 1-1 ) Pojo ( Plain Old Java Object )
* POJO 定義
    * 沒有繼承 ( 即父類別為Object )
    * 沒有實作介面
    * 沒有特別規範
* 在 Hibernate 中，常將 POJO 定義成符合 JavaBean 規範
    * 有預設建構子
    * 屬性皆為 private
    * 屬性都有對應的 Setter / Getter
* 此外，該類別一定要有物件識別屬性 ( OID )
    * 用於 Hibernate 底層運作
    * OID 對應資料庫端的主鍵 ( PK )
        * 可藉由映射檔的\<id\> 或 @Id 來設定
        * 可參考 4-2 使用映射檔、4-3 使用Annotation

## ( 1-2 ) POJO 其他稱呼
* 純粹拿來裝資料的物件(類別)，在業界常用不同的稱呼
    * POJO
    * Model
    * JavaBean
    * Entity
    * VO ( Value Object )
    * BO ( Business Object )
    * DO ( Domain Object )
* 這些名稱定義上其實不一樣，但太過學術討論，所以業界常拿來表示同一種物件 ( 類別 )

# ( 2 ) 資料型態對應
* 使用 POJO 來定義實體類別
    * Hibernate 的底層仍然需要 JDBC
    * 須先參考各 DBMS 廠商官方文件的 JDBC Data Type Mapping
* Hibernate 底層有 Hibernate Type
    * 負責映射 Java 端與資料庫端的資料型態
    * 在 JDBC 中用來儲存資料的資料型態都支援
    * 可參考 Guide-2.3.Basic types

# ( 3 ) Hibernate 實體物件的生命週期
![](https://i.imgur.com/R9P3WwM.png)
* 說明
    * 利用"實體物件"狀態改變的副作用，來間接操作資料庫
* 生命週期 ( Lifecycle ) => 臨時、永續、分離、移除
    * 臨時狀態 ( Transient states )
        * 尚未對應資料庫端的資料，不受 Hibernate 監控
        * OID ( object identifier ) 屬性沒有值
        * 剛透過 new 運算子實例化的物件，例如
            * Member member = new Member(); 
    * 永續狀態 ( Persistent states )
        * 有對應資料庫端的資料，會受到 Hibernate 監控
        * OID ( object identifier ) 屬性有值
        * 執行完 session 物件的 
            * get()
            * load()
            * save()
            * persist()
            * saveOrUpdate()
            * merge()
            * update()
        * 皆為永續狀態
    * 分離狀態 ( Detached states )
        * 有對應資料庫端的資料，但已脫離 Hibernate 的監控
        * OID ( object identifier ) 屬性有值，但無作用
        * 執行完 session 物件的
            * close()
            * detach()
            * evict()
            * clear()
        * 皆屬於分離狀態
    * 移除狀態 ( Removed states )
        * 對應資料庫端的資料已被刪除，不受 Hibernate 監控
        * OID ( object identifier ) 屬性有值，但無作用
        * 執行完 session 物件的
            * delete()
            * remove()
        * 皆為分離狀態
        * 只要物件變成此狀態，就不應重新使用，應等待被回收
